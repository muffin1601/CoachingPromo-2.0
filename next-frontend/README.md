# CoachingPromo Next.js migration

This app is standalone. `react-source/` is now owned application source (the name
records its origin), and `public/` contains its own versioned assets. Neither dev
nor build reads the original React frontend or backend folders.
Next owns its redesigned presentation in `components/design/` and
`styles/storefront.css`. `styles/square.css` is the final layout/theme layer:
3px corners, DM Sans typography, flat surfaces, fluid page shells and shared responsive gutters.
It deliberately keeps forms and modal dialogs bounded, and scrolls the design
canvas independently to preserve its editing coordinates on small screens.
The Next App Router uses the shared business components;
it does not run a nested BrowserRouter.
The dedicated `../next-backend` Express API runs on port 5001. Its current MongoDB
connection retains the existing data; the React backend remains independent on 5000.

## Run

1. Run `npm start` from `../next-backend` with its own environment settings.
2. Copy `.env.example` to `.env.local`, set `BACKEND_URL` and `NEXT_PUBLIC_SITE_URL`,
   and transfer the React CRM URL/key into `CRM_API_URL` / `CRM_API_KEY` if enabled.
3. Run `npm install`, then `npm run dev` (port 3000).
4. For production run `npm run build` and `npm start`.

Development writes to `.next-dev`; production build/start use `.next`. This keeps
webpack manifests and chunks isolated when a build runs alongside a dev server.
There is no source-sync step. Edit this app's files directly.
After changing this configuration, restart `npm run dev` and reload the browser.
Hydration warnings mentioning `bis_skin_checked`, `bis_register`, or
`__processed_*` indicate browser-injected attributes. Disable the extension on
localhost or test in a browser profile with extensions disabled; these attributes
are not generated by the app. Do not suppress hydration errors globally.

Next forwards `/api/*` and `/uploads/*` to `next-backend`. `/api/crm` forwards the original
lead payload to the configured CRM using a server-side API key. Payment, auth,
email, uploads, orders, admin and catalogue APIs remain on Express.
Keep payment/email/database credentials in `next-backend/.env`.
Its `FRONTEND_URL` is configured for Next on port 3000; update it for deployment.

## Parity

`route-parity.json` maps 28 original pages to Next routes. The old `/product/:slug`
URL redirects to the populated category/product URL. `/blog` and `/account` from
the earlier Next scaffold redirect to the React app's `/blogs` and `/profile`.
Homepage sections, navigation, footers, city links, chat, quote forms, institute
registration, search, favourites, cart, checkout, offers, blog comments/posting,
accounts, resets, SVG/PNG customizers and admin pages retain the original business
components. The header, hero, collections and homepage composition have Next-owned
replacements; the remaining pages receive the Next-only visual system.

`react-source/` and `public/` are no longer Git-ignored. Edit `react-source/` for
business components and `components/design/` or `styles/` for the presentation.
The obsolete sync/bootstrap scripts have been removed after backing them up.
Vite environment expressions and router imports have already been migrated.
The adapter preserves navigation state for customizers in session storage.
Browser-only canvas/admin code is loaded on the client; other components can render
on the server. API-loaded content retains the React app's client fetching behavior.
Next supplies initial route metadata. This is a parity migration, not a complete
conversion of database-backed page content to server components.

Cart, favourites and auth keep the React app's storage keys. Browser storage is
origin-specific, so moving to another host/port does not transfer existing sessions.
Existing accounts still work against the same database.

## Verify

`npm run verify:parity` checks route mappings and asset hashes against the committed
`asset-manifest.json`, without the original folders. After deliberate asset edits,
refresh the baseline with `node scripts/capture-assets.mjs` and review the diff.
`npm run lint` checks the Next adapters; `npm run build` compiles all routes.
`node scripts/check-standalone.mjs` creates an isolated app pair, installs from the
lockfiles offline without lifecycle scripts, then runs the production build and tests.
Before launch, test with the configured backend: login/reset, product-to-customizer
navigation, cart persistence, quote/catalogue submissions, admin access/uploads,
blog comments, and a Razorpay test-mode checkout. No live payment or CRM submission
is performed by the parity checker.

Verification on 2026-09-26: production build passed; adapter lint passed; 28 page
mappings plus the product redirect and 799 byte-identical assets passed parity
checks. `node scripts/smoke-next.mjs` passed 40 read-only HTTP checks against the
production server and the existing MongoDB-backed API. Set `SMOKE_URL` to use a
different local port (default `http://127.0.0.1:3100`). Browser automation was
unavailable, so visual checks and interactive payment/CRM/customizer flows remain
unverified. The dedicated backend's `FRONTEND_URL` points at Next on port 3000.
